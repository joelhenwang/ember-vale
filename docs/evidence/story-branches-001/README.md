# story-branches-001: branch a story from any past turn

## Question

The owner decided: from any earlier turn, a player (or watcher) starts a NEW story that
continues from the end of that turn, and the original stays untouched. The branch must be the
story's real state at that turn (people, items, rumours, relationships, memories, intentions,
history, clock, map, the player's character and role), with new ids everywhere and nothing
regenerated by a model. Can the state at an earlier turn be rebuilt from what is already
stored, or must it be kept from now on?

## Finding: past state cannot be rebuilt exactly

What is stored per turn today, read in the code and the schema (migrations 0001-0057):

| Store | What it keeps | Enough to rebuild a past turn? |
|---|---|---|
| `phase_snapshot` + `phase_snapshot_character` | per beat: character id + version, a content hash | No: versions only, no values |
| `world_event` + `event_effect` | ordered effects (`move_entity`, `advance_clock`, `resource_adjusted` with a delta, observations, memories, `item_found`, `hook_settled`) | No: see below |
| `created_phase_index` columns | when observations, memories, digests, hooks, entities were made | Only for rows that are never changed afterwards |

Most story state is **updated in place** by the repositories, with no history:
`character_state` (place, stamina, mana, conditions, life), `item_instance` (owner, place,
quantity; `remove_item` **deletes** rows), `travel_route` (updated and **deleted**),
`relationship`, `belief`, `character_skill`, `narrative_hook` (status, ending), `activity`
(progress, status), `character_intention` (replaced each turn), `world` (status, version),
`world_clock`, `world_config` (director counters), `intervention` (status), `autoplay`,
`aggregate_version`, `dnd_party_member`/`dnd_monster` (hit points), and the salience of
`observation`/`recent_memory` (raised at day's end by `bump_salience`). Many of these changes
are not effects at all (intentions, hooks opened by the director, travel activities, item
take/transfer, party sheets), and the ones that are cannot be reversed exactly: resource deltas
are clamped, deleted rows are gone. So **(a) exact reconstruction is not possible** for any turn
played before this change.

## Decision: (b) keep a checkpoint at the end of every turn from now on

* **Migration 0058** adds `story_checkpoint` (world, turn, event cursor, schema version, one
  JSONB document) and `story_branch` (provenance). Both are tables of their own, so story
  creation still works against older schemas (`test_preset_revisions` old-schema trap).
* **Capture** (`SqlAlchemyCheckpointRepository.capture`, called by
  `Stage1Orchestrator._keep_turn`): one `INSERT ... SELECT jsonb_build_object(...)` built
  entirely inside Postgres from every changeable row of the story (37 tables) plus the event
  cursor (`max(world_event.sequence)`). The safe boundary is the end of the turn: after its
  scenes commit; on the turn that ends a day, after the day's summaries and digests (they
  belong to that turn), in the same background task the next beat already waits for. A capture
  failure is logged, never raised: the turn stands, it just cannot be branched.
* **Kept small:** config values over 2 KB (the map, place maps, portrait frames, written at
  story creation) are kept as an md5 fingerprint; a branch takes the live value only if it still
  matches, otherwise the turn is refused. Salience only moves at day's end, so a turn inside a
  day points at the day-end turn before it instead of repeating the map (63 KB a turn at 300
  turns before this; 10.8 KB after).
* **Branch** (`application/stories/branch.py`, copy in
  `infrastructure/repositories/checkpoints.py`): changeable state from the checkpoint; history
  that is only ever added to (events and effects up to the cursor, runs and snapshots, scenes,
  intents, attempts, reactions, resolutions, narration, observations, memories, digests,
  summaries of completed days, recall vectors, finished pictures) from the live tables. One
  transaction. Every id is renamed; runs and snapshots keep their derived form
  (`derive_run_id(new world, index)`), as do intents, attempts, reactions and resolutions, so the
  engine finds them again. A column pointing at a source row that is not copied (task runs,
  model calls) becomes empty; ids inside text and JSON are renamed in both spellings (uuid and
  hex: `journey:<scene hex>:...`, `obs:<uuid>`). Pictures share the stored file through a new
  asset row (`content_ref` kept); pending or running image jobs are never copied; nor are model
  calls, costs, task runs, outbox messages or autoplay (the branch starts paused). Queued
  Director/God requests come along as they stood at the turn.
* **Refused, plainly, never approximated:** a turn played before 0058 (no checkpoint): "This
  turn was played before turns were kept for branching, so its exact state isn't stored. Turns
  played from now on can be branched." A turn still being written (its narration or day-end
  work is running): "This turn is still being written. Try again in a moment." A turn not
  played: "That turn hasn't been played yet." The UI only offers "Branch from here" on turns
  `GET /stories/{id}/branch-points` lists, so a control is never shown that would be refused.

## What changed

* Backend: `POST /stories/{story_id}/branch` (`absolute_index`, optional `title`,
  `Idempotency-Key`; replays like story creation through `story_creation_receipt`),
  `GET /stories/{story_id}/branch-points`, `branched_from` on `StorySummary` and `StoryDetail`
  (story, title, turn, "Day 1, morning"). Default title: "<story> — from Day N, <time>" (a branch
  of a branch keeps one suffix).
* Frontend: "Branch from here" on Adventure's turn headings, on Watch's feed headings and in the
  event view; `BranchDialog.vue` says what happens (new story from the end of this turn, the
  original stays as it is, pictures still being painted stay behind, the new name) and opens
  the new story on its screen; story cards show "Branched from <story> at Day N, <time>".

## Verification

* `tests/test_story_branches.py` (3 tests, real story from the built-in vale, Wren as the
  player, scripted fake model): after 5 turns (Wren walks off, a second rumour opens), a branch
  from turn 2 equals the source's state recorded right after turn 2, table for table, once its
  ids are renamed back; the source is byte-identical before, after the branch and after two
  turns played on the branch; no row of the branch contains a source id (only
  `story_branch.source_world_id` and asset `content_ref` may); idempotent replay, key reuse with
  another body is a 409; not played / not kept are refused with the plain messages; the turn
  that ends a day carries the day's summaries (the turn before it does not); a turn of day 2 has
  the same salience totals as the source after day 1's bumps.
* Full backend suite: 934 passed, 1 skipped; ruff, format, basedpyright 0 errors; TS client
  `--check` clean. Frontend: eslint, vue-tsc, vitest 461 passed, vite build.
* Screenshots (headless Edge, fake provider, `branch-shots.mjs`, results in `shots.json`):
  `1-adventure-branch-action`, `2-confirmation`, `3-new-story-open`, `4-stories-provenance`,
  `5-watch-feed`, `6-watch-event-view`, `7-watch-confirmation`, `8-confirmation-phone`. The one
  console 403 is the dev server refusing a file outside the worktree (node_modules junction),
  not the feature.

## Known gaps

* Turns played before migration 0058 cannot be branched (said in the UI, refused by the API).
* A branch's next turn re-runs nothing from the past; Background narration of a scene that was
  never written (a crash mid-narration) is copied as unwritten and would be written by the
  branch's next beat, as it would be in the source.
* No rewind in place and no deleting old checkpoints; the old-schema trap was avoided, not
  extended.

## After the merge into main (2026-10-09)

The dev API was rebuilt on merged main (`e1cb79e`). It migrated to `0058_story_checkpoints` after a fresh backup (`20261009-092035`). `live_branch_check.py` then ran on the live combat story "Live goblin check" (Venice), results in `live-branch-main.json`:
- Branch points listed only turns 4 and 5, the two played after the migration; turns 1–3 predate it and are refused.
- A branch from turn 4 matched the source as it stood after turn 4: turn 4, 12 events, Wren 12/12, the goblin 5/7.
- The branch played its own turn 5 (16 events), and the source stayed exactly as it was.
- The Stories list shows the branch with "Branched from Live goblin check at Day 1, afternoon" (`live-stories-main.png`, `stories-shot.mjs`), with no page errors.
