E3 lifecycle decisions (2026-09-21): new presets stay local (studio.ts drafts) until Publish sends one complete validated `create_preset` — no placeholder rev 1. After publication the receipt survives completion, so identical retries replay; `complete` retires only the receipt-matching version (newer edits need explicit discard); `discard` voids the receipt. Publish renames update the preset display name atomically; revision payloads stay immutable.

E3 publication corrections (2026-09-22, committed `261d32d`): receipts are per draft/version (migration 0037, PK `(draft_id, draft_version)`), so publish → edit → save → publish lands a new revision under its own receipt and every earlier publication still replays. Replay resolves the requested draft's receipt even while a successor draft occupies the preset, without touching it. `POST .../publish` returns `PresetPublishView{published_revision, detail}` so replay names the exact revision apart from the Library head (contract regenerated: `content/schemas/openapi.json`, `content/clients/worldsim.ts`, `PresetPublishView` added to the generator's model list). Corrected the "versions advance only when fields change" claim: every successful save advances the version, so a matching version implies matching fields. Verified: 17/17 draft service + HTTP replay tests, 29/29 with library neighbors, ruff clean on touched files, frontend 131/131 + typecheck + lint clean. Pre-existing failures unrelated to this change (identical on clean `c89e1e1` tree): `test_domain_schema` committed-bundle drift, 3× `test_revamp_p09` + 1× `test_revamp_p08` activity-completion stalls, plus ruff/basedpyright noise in untouched files. Full backend suite is NOT green: five pre-existing failures tracked separately — `test_domain_schema` committed-bundle drift, 3× `test_revamp_p09` + 1× `test_revamp_p08` activity-completion stalls (comparison commit `c89e1e1` via `git stash`, `uv run pytest`, `ruff check`, `basedpyright`, then restore and re-run). Evidence outputs committed in `261d32d` (`evidence/stage2-seven-day-v1/`, `evidence/stage3-soak-v1/`, `evidence/stage3-thirty-day-v1/`, `evidence/stage5-generation-v1/`, `docs/stage3-quality-baseline-v1.json`) are retained deliberately as suite baselines.

New `useEditorDraft` opens/hydrates/saves/publishes/completes/discards with frozen draft+version identity per operation and saving/saved/failed/publishing/published states; `studioFields` packs only exposed keys (character personality/background, world description/lore/locations/starting key) so unexposed payload fields survive verbatim, with round-trip tests. Both studios show the states with retry, publish new revisions, and return to the wizard with an adoption offer the wizard applies only on explicit accept (`adoption.ts`: world re-pins, character re-pins the matching member, input never mutated; journey unit proof shows a new story on the adopted revision while the original selections are unchanged). First publication is deliberately NOT wired to `create_preset`: the server receipt that would make the key effective is still pending, so no second creation path exists yet. Verified: frontend 149/149 + typecheck + eslint + prettier clean; backend E3 scope 17/17 green. E6, recovery, and creation-departure remain closed; browser journey proof still pending environment.

E3 first-creation corrections (2026-09-22, uncommitted): first creation IS wired — the frozen idempotent request creates revision 1 and the studios hand off to the real preset on the receipt (the earlier "first publication remains unwired" note is superseded). While a creation is unresolved, retries replay the original frozen request under its original key; newer edits are stashed as superseded and stay available, a replay recovery records the preset id and stays on the page with an apply/open offer, and a second preset is minted only through the explicit separate-preset action (`submitFresh`). A memory-only freeze is flagged via `requestPersisted` and never presented as reload-safe. No further publication wiring is outstanding for creation itself. Proof: `usePresetCreation` unit regression (replay-under-changed-form, recovery reload, explicit-fresh, memory-only) plus walkthrough `firstcreate` ambiguous-creation case and a full `twostories` proof (story B created from the adopted draft, both played, both reloaded with independent setups and runtimes). E6, recovery, and creation-departure remain closed.

E3 dismiss-bypass correction (2026-09-23, uncommitted): dismissing the recovery notice hid it but also forgot the creation, so an ordinary Create after Dismiss minted a second preset. Dismiss now hides only the notice (`noticeDismissed`, persisted): the recovered-preset association and the set-aside edits survive dismissal and reload, and ordinary `submit` stays blocked until an explicit separate preset. `discardNewerEdits()` explicitly forgets the set-aside edits while keeping the association; `submitFresh()` is the sole path to a new identity. The dismissed state shows a compact association line (Open / Create separate / Discard newer edits) instead of the ordinary Create button. Proof: new unit regression (Dismiss → ordinary Create blocked, reload still blocked, discard keeps association, only separate mints) plus two `firstcreate` browser checks. The 2026-09-22 18-check `firstcreate`+`twostories` subset is preserved durably (`results-firstcreate-twostories-2026-09-22.json` + PROVENANCE note); the temporary output is no longer the only record.

E3 wizard-origin handoff (2026-09-23, uncommitted): a wizard-originated creation now returns to `/new-story` with an explicit adoption offer for revision 1 (`adopt_created=1`, bound to the calling draft) — never an automatic pin. The wizard refreshes the shelf at accept so a brand-new preset is not mistaken for unknown; accepting a world offer switches the draft's world, accepting a character offer re-pins a matching member or adds a known preset to a non-full cast (new `apply-character-add`/`cast-full` plans, `MAX_CAST=6`; dismissing a failed add-accept removes the added member). Entry points: the cast step's CreateCharacterTile is wired to `/new-story/character/new?draft=`, and the world step gains an "Or shape a new world" link. Proof: `adoption.spec` plan cases plus three `firstcreate` browser checks (world offer → pins rev 1; character offer → joins cast at rev 1, world pin untouched). E6, recovery, and creation-departure remain closed.

E3 character-add rollback (2026-09-23, uncommitted): a character-add accept may hand the newcomer control; when persistence failed and the user dismissed, the added member was removed but `controlledKey` kept pointing at it. `PinSnapshot` now captures the controlled selection, `pinsEqual` compares it (a deliberate reselection counts as an intervening edit and skips the restore), and `restoreSnapshot` writes it back alongside membership, revisions, and locations — so dismissal never persists a controlled key absent from the restored cast. Proof: `adoption.spec` snapshot/compare/restore cases plus a new `addrollback` browser scenario (10/10: uncontrolled player draft, failed accept controls Ash locally, failed dismiss keeps recovery, retry dismiss removes Ash and restores no-control, reload clean on server and UI, intervening location preserved with the server untouched). Evidence in `results-addrollback-2026-09-23.json` + PROVENANCE note.
